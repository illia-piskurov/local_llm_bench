## 1. Project Overview

`local_llm_bench` is a high-performance, modular benchmarking suite for evaluating local Large Language Models (LLMs) served via LM Studio, Ollama, or OpenAI-compatible endpoints.

### Key Objectives:
- **Code Quality Evaluation**: Automated verification of multi-level algorithmic, systems, and polyglot coding tasks (Python, C99, JavaScript, Lua).
- **Execution Sandboxing**: Zero-overhead, isolated guest code execution (MicroPython WASM with fuel-metering, Zig C99 WASM via Wasmtime, QuickJS with virtual timers, and Lupa Lua).
- **Speed & Latency Profiling**: Tracking tokens per second (`tok/s`), Time-to-First-Token (`TTFT`), and reasoning thought tokens (`think tok`).
- **Conflict-Free Multi-Device Git Synchronization**: Clean, structured JSON records (`records/`) synchronized bidirectionally with a local SQLite cache (`bench.db`) to avoid Git merge conflicts across machines (e.g., MacBook, ThinkPad, Linux workstation).
- **Reasoning Model Support**: First-class support for reasoning LLMs (DeepSeek-R1, QwQ, etc.) with automatic `<think>` tag stripping, draft shielding, and thought chain logging.
- **Standalone Dashboard & MCP Server**: Zero-dependency dark-mode HTML report (`report.html`) and Model Context Protocol (MCP) server (`mcp_server.py`) for AI pair programming.

## 3. Core Subsystems

### 3.1. Benchmarks (`benchmarks/`)
Every benchmark is completely self-contained in a single module under `benchmarks/`:
- **Prompts**: `LEVEL1_PROMPT`, `LEVEL2_PROMPT`, `LEVEL3_PROMPT`.
- **Test cases**: Pure data structures or test functions executing inside isolated sandboxes.
- **Verification**: Assertion logic returning `(passed, total, failures)`.
- **Benchmark Class**: Subclasses `Benchmark` defined in `benchmarks/base.py`.

### 3.2. Sandboxes (`sandboxes/`)
Untrusted code generated by models must **never** run directly on the host machine without sandboxing:
- **Python**: Runs in MicroPython WASI via `sandboxes/python_wasm.py` with fuel counting (deterministic instruction-level timeout protection). There is no native fallback execution.
- **C99**: Compiled on the fly via `ziglang` to `wasm32-wasi` and executed inside `wasmtime` with zero disk/network capability.
- **JavaScript**: Executed in `quickjs` using a virtualized zero-latency timer queue and polyfilled `AbortController` / `AbortSignal`.
- **Lua**: Executed in `lupa` with standard library privileges revoked (`os`, `io`, `package`, `debug` set to `nil`).

#### 3.2.1. Python MicroPython Compatibility Layer (`sandboxes/mpy_compat.py`)
To maintain complete security isolation without sacrificing model ergonomics or failing valid solutions, the Python sandbox runs on **MicroPython WASI** with an AST-driven **CPython standard library compatibility layer**:
- **Design Philosophy**: LLMs are naturally trained on modern CPython 3.10+ idioms (`typing`, `deque`, `defaultdict`, `itertools`, `heapq`, etc.). Demanding that models produce raw MicroPython code causes unnecessary hallucination and fails otherwise sound algorithmic solutions. Instead of weakening sandboxing or prompting models to avoid standard Python constructs, `sandboxes/mpy_compat.py` transparently shims required CPython modules.
- **Selective AST Injection**: Before passing guest code to MicroPython, the sandbox parses its AST to detect imported modules. Only the shims matching actual `import ...` or `from ... import ...` statements are injected at the head of the script. This minimizes parse overhead and preserves deterministic fuel limits.
- **Supported Shimmed Modules & Features**:
  - `typing`: `Any`, `Optional`, `Union`, `List`, `Dict`, `Set`, `Tuple`, `Callable`, `Iterable`, `Sequence`, `Mapping`, `TypeVar`, `Generic`, `Protocol`, `cast`, `overload`.
  - `copy`: `copy`, `deepcopy` (handles nested dicts, lists, sets, tuples, and custom class instances).
  - `collections`: `deque` (with `append`, `appendleft`, `pop`, `popleft`, `extend`, `maxlen`), `defaultdict`, `Counter` (`most_common`, arithmetic counters), `OrderedDict`, `namedtuple`.
  - `functools`: `lru_cache`, `cache`, `wraps`, `reduce`, `partial`, `total_ordering`.
  - `itertools`: `chain`, `combinations`, `permutations`, `product`, `islice`, `cycle`, `repeat`, `accumulate`, `groupby`, `takewhile`, `dropwhile`.
  - `bisect`: `bisect_left`, `bisect_right`, `bisect`, `insort_left`, `insort_right`, `insort`.
  - `abc`: `ABC`, `abstractmethod`.
  - `heapq`: CPython compatibility additions on top of MicroPython's built-in heap primitives (`nlargest`, `nsmallest`, `heappushpop`, `heapreplace`).
- **Unshimmable MicroPython Limitations** (Agents designing tests or benchmarks must keep these in mind):
  - No `dataclasses` or standard `enum.Enum` (use lightweight classes or tuples instead).
  - Recursion depth is capped at ~100 frames; prefer iterative algorithms.
  - Native integers in MicroPython WASI are 31/32-bit signed ints without arbitrary precision bignum in some builds; avoid integers exceeding `2**31 - 1`.
  - Dictionary iteration order is not guaranteed to be insertion-ordered across all MicroPython operations.
- **Verification**: All shims are verified against native CPython behavior via `tests/test_mpy_shims.py`.

### 3.3. Git Synchronization & Storage (`records/` & `sync.py`)
- SQLite database `bench.db` is a **local read/write cache** (listed in `.gitignore`).
- All persistent test results and speed measurements are stored as atomic JSON files in `records/` partitioned by host and run ID (`{host_id}__{run_id}__{model}_{benchmark}_{level}.json`).
- `sync.py` performs fast (<100ms) bidirectional sync with content-hash check (`_write_if_changed`) to prevent unnecessary Git churn:
  - SQLite -> `records/` on test run.
  - `records/` -> SQLite on runner launch or `python main.py sync`.
  - Non-destructive upserts preserve completion timestamps and avoid cascade deletions.
- **Result**: Zero merge conflicts when switching between different laptops or branches.

### 3.4. Hardware Profiling (`host_configs.py`)
- Automatically detects CPU model, RAM size, OS, and hostname without external dependencies.
- Binds the current machine to a host ID in `.local_host` (git-ignored).
- Results gathered on a Mac M3 will never overwrite or pollute ThinkPad or Linux speed metrics.

### 3.5. Inference Client & Reasoning (`lmstudio.py`)
- Connects to LM Studio, Ollama, or remote endpoints. Address stored in `.local_server` (git-ignored).
- Automatically extracts reasoning blocks (`<think>`, `<thought>`, `<reasoning>`) and logs them to `raw_answers/<model>_<bench>_<level>.reasoning.txt`.
- Strips reasoning thoughts before code block extraction so draft code inside thoughts is never accidentally executed.
- Omits `temperature` by default so model-specific sampling presets configured in LM Studio (e.g., recommended 0.6 for DeepSeek-R1) remain active.

## 4. Commands & Workflows

### Running the Benchmark Suite
```powershell
# Interactive CLI menu (default entry point)
python main.py

# Generate HTML dashboard (opens in browser)
python main.py report

# Manually synchronize SQLite cache with records/
python main.py sync

# Manage and delete model results, speeds, and runs
python main.py delete
```

### Testing & Verification
```powershell
# Run full pytest suite (all sandboxes, contracts, and golden solutions)
uv run pytest

# Run linting with Ruff
uv run ruff check

# Format codebase with Ruff
uv run ruff format
```

## 5. Development Rules & Guidelines

1. **Language Policy**:
   - Write all code comments, docstrings, markdown files, and commit messages in **English**.
   - User interaction in chat can be in the user's preferred language, but project files must remain strictly English.
2. **Safety & Sandboxing**:
   - Never execute model code on the raw host process without timeout protection or sandboxing.
   - Always import execution helpers from `sandboxes`.
3. **Git Hygiene**:
   - Never commit `bench.db`, `*.db-wal`, `*.db-shm`, `.local_host`, `.local_server`, `report.html`, `.agents/`, or `__pycache__`.
   - All shared benchmark runs must be saved into `records/` via `storage.py`.
4. **Code Quality**:
   - Maintain strict type annotations (`mypy`/`pyright` compatible).
   - Keep line length within 120 characters as configured in `pyproject.toml`.
   - Run `uv run ruff check` and `uv run pytest` before concluding any task.
