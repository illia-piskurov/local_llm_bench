We need to implement a task scheduler. Let's think about the algorithm.

Tasks: dict name -> (duration, deps, priority). Workers: int.

Rules:
- Non-preemptive.
- At most workers tasks run simultaneously.
- Ready tasks selection: highest priority, then shortest duration, then alphabetical name.
- When multiple tasks start at same timestamp, append to returned list following same tie-breaking rule.
- Cyclic dependency -> None.

So essentially a priority queue based scheduler with a worker pool. At each time step, we pick up to `workers` ready tasks in priority order and start them. Since non-preemptive, once started they run for duration.

Implementation: use a min-heap with key (-priority, duration, name). Maintain a ready set of tasks whose deps are all finished. At each tick, pop up to workers tasks, record start time, add to running dict. Advance time by min duration among running. When a task finishes, add to ready.

But careful: "When multiple tasks start at the exact same timestamp, append them to the returned list following the same priority tie-breaking rule" — that's naturally handled since we pop in order.

Edge cases: workers <= 0? Probably return None or handle. If workers <= 0, nothing runs — return None? Let's return None if workers <= 0.

Cycles: detect with topological sort (Kahn's) before scheduling.

Also tasks with no deps are ready initially.
